# [v1.2.0] - 2026-04-15

## Summary

Major documentation restructure and GitHub project standardization.

## Added

### Documentation
- Expanded README.md with comprehensive badges, performance highlights, and 6-week learning path
- FAQ guides (English: `docs/en/faq.md`, Chinese: `docs/zh/faq.md`)
- Troubleshooting guides (English: `docs/en/troubleshooting.md`, Chinese: `docs/zh/troubleshooting.md`)

### GitHub Templates
- Issue templates: bug report, feature request, documentation improvement
- Pull request template with test checklist
- `SECURITY.md` security policy
- `CODE_OF_CONDUCT.md` contributor covenant

### Developer Tools
- Helper scripts in `scripts/` directory:
  - `build.sh` - Build automation
  - `test.sh` - Test runner
  - `format.sh` - Code formatting
  - `setup.sh` - Environment setup
- `.editorconfig` for consistent coding style across editors

## Changed

### Structure
- Consolidated `DOCS.md` into `README.md` (single entry point)
- Moved `CLAUDE.md` to `docs/developers/claude-guide.md`
- Moved `package.json`, `package-lock.json`, `book.json` to `docs/` subdirectory
- Reorganized `tools/` to `tools/performance/`

### Documentation
- Unified all 5 example module READMEs with consistent structure:
  - Module title and badge
  - One-line description
  - Contents table
  - Key concepts
  - Running benchmarks
  - Expected results
  - Further reading
- Updated `gitbook-sync.md` (en/zh) to reference `README.md` as entry point

## Fixed

- All workflow branch references (`main` → `master`)
- `pages.yml` npm cache configuration
- Changelog file naming consistency
- All internal documentation links

## Migration Notes

If you have bookmarks or scripts referencing:
- `DOCS.md` → Use `README.md` instead
- `CLAUDE.md` → Use `docs/developers/claude-guide.md`
- `tools/analysis/` or `tools/flamegraph/` → Use `tools/performance/`
