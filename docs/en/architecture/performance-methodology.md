# Performance Methodology

The repository favors a simple chain of evidence: reproduce, measure, change one variable, and verify with the appropriate preset or benchmark.

## Working rules

1. Start from the preset-driven validation path.
2. Profile before claiming a bottleneck.
3. Use benchmarks to compare alternatives, not to justify unchecked code.
4. Record trade-offs in docs or OpenSpec when a change alters repository posture.
