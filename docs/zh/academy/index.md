# 学院

学院部分是这份白皮书的读者定向层。它说明应当如何进入仓库、教学模块如何映射到代码，以及在阅读过程中应始终保留哪些验证纪律。

## 本节作用

- 把仓库从一组目录列表转换成可辨识的学习结构
- 在读者接触基准数字或并发结论之前，先定义证据标准
- 保留原有学习路径，但不让它掩盖更高层的架构叙事

## 阅读模式

| 读者姿态 | 建议起点 | 原因 |
| --- | --- | --- |
| 评估技术深度的审阅者 | [模块总览](/zh/academy/module-atlas) | 该页把每个主题直接对应到具体代码、测试与基准。 |
| 检查严谨性的维护者 | [验证原则](/zh/academy/validation-doctrine) | 该页定义了整站文档与代码评审共用的证据阶梯。 |
| 想尽快进入可运行状态的实践者 | [快速开始](/zh/getting-started/quickstart) | 它先带你获得一个经过验证的本地构建，再进入更深层阅读。 |
| 希望按原始教学顺序学习的读者 | [学习路径](/zh/guides/learning-path) | 它保留了示例模块的教学推进顺序。 |

## 学院核心页面

| 页面 | 回答的主要问题 | 结果 |

| [模块总览](/zh/academy/module-atlas) | 哪个仓库表面教授哪个概念？ | 得到一张从模块到代码、测试与基准的映射表。 |

## 推荐顺序

1. 先阅读[首页](/zh/)，理解仓库的核心论点与验证主张。
2. 使用[模块总览](/zh/academy/module-atlas)选择一个模块或子系统。
3. 在相信基准数字或并发结论之前，先读[验证原则](/zh/academy/validation-doctrine)。
4. 当你需要仓库级背景时，转入[架构](/zh/architecture/)。
5. 当你需要命令而不是解释时，转入[实践手册](/zh/playbook/)。

## 与站点其他部分的关系

学院并不试图成为一门面向初学者的完整课程。它是为熟练读者准备的定向层，目标是快速回答三个问题：

1. **关键代码在哪里？**
2. **它如何被验证？**
3. **我接下来该读哪一页来确认或质疑一个结论？**

如果你已经非常熟悉该项目，可能只需要[参考](/zh/reference/)和[研究](/zh/research/)部分。对其他读者而言，学院仍是最短的、纪律明确的首读路径。
