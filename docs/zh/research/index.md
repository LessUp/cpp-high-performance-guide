# 研究

研究部分把仓库放回更广阔的性能工程语境中。它的存在，是为了让读者不仅能评估仓库教了什么，还能看清这些建议背后依赖了哪些公开参考、工具与设计传统。

## 为什么需要这一节

- 展示仓库结论背后的外部材料
- 将本项目与相邻的公开仓库、库和工程参考进行比较
- 解释为什么仓库如今更偏向收口、加固与低频维护，而不是无边界扩张

## 研究入口

| 页面 | 内容 | 最适合的用途 |
| --- | --- | --- |
| [相关工作](/zh/research/related-work) | 对公开仓库、库与知名性能资料的比较说明 | 校准本项目是什么，以及它不是什么 |
| [参考资料](/zh/research/references) | 精选标准、手册、文章与工具文档书架 | 在阅读示例或架构页时核对外部权威来源 |
| [演进记录](/zh/research/evolution) | 仓库姿态、取舍与面向收口的维护说明 | 理解当前结构为何呈现为现在的样子 |

## 在这里，什么算研究

本项目中的研究刻意保持务实。一个有用的来源通常至少满足以下之一：

- 解释示例所依赖的某个低层机制
- 提供可以在本地复现的测量方法
- 展示值得拿来比较的公开实现策略
- 澄清某项取舍为什么是真问题，而不只是流行说法

## 推荐阅读顺序

1. 先读[相关工作](/zh/research/related-work)，给仓库定位。
2. 在阅读示例或架构页时，把[参考资料](/zh/research/references)当作来源书架。
3. 最后以[演进记录](/zh/research/evolution)收束，理解当前维护姿态。

研究部分让整套文档更接近一部工程专著，而不是一组仅仅拥有更漂亮首页的教程集合。
